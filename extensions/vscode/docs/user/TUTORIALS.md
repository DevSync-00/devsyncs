## Quick Start Tutorial

### Step 1: Install DevSync

1. Open VS Code
2. Press `Ctrl+Shift+X` (Windows/Linux) or `Cmd+Shift+X` (Mac)
3. Search for "DevSync"
4. Click **Install**
5. Click **Reload** when prompted

### Step 2: Configure DevSync

1. Open Command Palette (`Ctrl+Shift+P` / `Cmd+Shift+P`)
2. Type: `DevSync: Configure Settings`
3. Enter your API credentials:
   - **API URL**: `https://api.Dev-Sync.dev`
   - **API Key**: Your API key (get from dashboard)
   - **Project ID**: Your project ID

### Step 3: Open Your Prisma Project

1. Open the folder containing your `schema.prisma` file
2. DevSync will automatically detect your Prisma project

### Step 4: Run Your First Scan

1. Open the DevSync sidebar (click the DevSync icon)
2. Click **"Scan Schema"**
3. Wait for the scan to complete
4. View results in the sidebar

**Congratulations!** You've completed your first scan.

## First Schema Scan

### Prerequisites

- A Prisma project with a `schema.prisma` file
- A database connection (optional, but recommended)

### Tutorial Steps

#### 1. Prepare Your Schema

Ensure your `schema.prisma` file is valid:

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id    Int    @id @default(autoincrement())
  email String @unique
  name  String?
}
```

#### 2. Configure Database Connection

1. Open Settings (`Ctrl+,` / `Cmd+,`)
2. Search for "DevSync Database"
3. Set `devsync.databaseConnection`:
   ```
   postgresql://user:password@localhost:5432/mydb
   ```

#### 3. Run the Scan

**Method 1: Using Sidebar**
1. Open DevSync sidebar
2. Click **"Scan Schema"** button
3. Watch progress in the status bar

**Method 2: Using Command Palette**
1. Press `Ctrl+Shift+P` / `Cmd+Shift+P`
2. Type: `DevSync: Scan Schema`
3. Press Enter

#### 4. View Results

After the scan completes:
- **Sidebar**: See all mismatches organized by type
- **Editor**: See inline diagnostics (squiggly lines)
- **Status Bar**: See summary information

#### 5. Understand Results

- **Red indicators**: Critical errors (missing tables, type mismatches)
- **Yellow indicators**: Warnings (optional fields, constraints)
- **Blue indicators**: Informational (suggestions, optimizations)

## Applying Your First Fix

### Scenario

You've scanned your schema and found a missing field in your database.

### Tutorial Steps

#### 1. Identify the Mismatch

1. Open the DevSync sidebar
2. Find the mismatch in the list
3. Click on it to see details

Example mismatch:
```
Missing Field: "email" in model "User"
Severity: Error
Suggested Fix: ALTER TABLE "User" ADD COLUMN "email" TEXT;
```

#### 2. Review the Suggested Fix

1. Click on the mismatch
2. Read the suggested fix
3. Understand what will change

#### 3. Apply the Fix

**Option A: Apply via Code Action**
1. Open your `schema.prisma` file
2. Find the diagnostic (squiggly line)
3. Click the lightbulb icon (💡)
4. Select **"Apply Fix"**

**Option B: Apply via Sidebar**
1. Right-click on the mismatch in sidebar
2. Select **"Apply Fix"**
3. Review the preview
4. Click **"Apply"**

#### 4. Verify the Fix

1. Check your schema file
2. Verify the change was applied correctly
3. Run another scan to confirm the mismatch is resolved

## Generating Migrations

### Scenario

You have multiple mismatches and want to generate a migration file.

### Tutorial Steps

#### 1. Run a Scan

1. Ensure you have recent scan results
2. If not, run a scan first

#### 2. Review Mismatches

1. Open the sidebar
2. Review all detected mismatches
3. Ensure they're all valid

#### 3. Generate Migration

**Method 1: Using Sidebar**
1. Click **"Generate Migration"** in sidebar
2. Wait for generation to complete

**Method 2: Using Command Palette**
1. Press `Ctrl+Shift+P` / `Cmd+Shift+P`
2. Type: `DevSync: Generate Migration`
3. Press Enter

#### 4. Review Migration File

1. The migration file opens automatically
2. Review the SQL statements
3. Make any necessary adjustments

Example migration:
```sql
-- Migration generated by DevSync
-- Timestamp: 2024-01-15T10:30:00Z

ALTER TABLE "User" ADD COLUMN "email" TEXT;
ALTER TABLE "User" ADD COLUMN "createdAt" TIMESTAMP DEFAULT NOW();

CREATE INDEX "User_email_idx" ON "User"("email");
```

#### 5. Apply Migration

1. Use your migration tool (Prisma Migrate, etc.)
2. Or use Command Palette: `DevSync: Apply Migration`
3. Verify the migration was applied successfully

## Using the Chat Assistant

### Scenario

You want to understand a mismatch or get help with your schema.

### Tutorial Steps

#### 1. Open Chat Panel

1. Click the **Chat** icon in the Activity Bar
2. Or use Command Palette: `DevSync: Open Chat`

#### 2. Ask a Question

Type your question in the chat input:

Examples:
- "What fields are missing in the User model?"
- "How do I add a unique constraint?"
- "Explain the difference between my schema and database"

#### 3. Get AI-Powered Answers

The chat assistant will:
- Analyze your scan results
- Provide context-aware answers
- Suggest solutions
- Show code examples

#### 4. Follow Suggestions

1. Review the AI's suggestions
2. Apply fixes directly from chat (if available)
3. Ask follow-up questions

### Example Conversation

**You**: "What's wrong with my User model?"

**DevSync**: "I found 2 issues with your User model:
1. Missing field 'email' in database
2. Type mismatch: 'age' is Int in schema but TEXT in database

Would you like me to generate fixes for these?"

**You**: "Yes, please fix the email field"

**DevSync**: "I've generated a fix. Click 'Apply Fix' to add the email field to your schema."

## Setting Up CI/CD Integration

### Scenario

You want to check for schema mismatches in your CI/CD pipeline.

### Tutorial Steps

#### 1. Install DevSync CLI

```bash
npm install -g @devsync/cli
# or
yarn global add @devsync/cli
```

#### 2. Configure Environment Variables

Set these in your CI/CD environment:
```bash
export DEVSYNC_API_URL="https://api.Dev-Sync.dev"
export DEVSYNC_API_KEY="your-api-key"
export DEVSYNC_PROJECT_ID="your-project-id"
export DATABASE_URL="postgresql://..."
```

#### 3. Add to CI/CD Pipeline

**GitHub Actions Example**:
```yaml
name: Schema Check

on: [push, pull_request]

jobs:
  check-schema:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      
      - name: Install DevSync CLI
        run: npm install -g @devsync/cli
      
      - name: Run Schema Scan
        run: devsync scan --db ${{ secrets.DATABASE_URL }} --fail-on-mismatch
        env:
          DEVSYNC_API_KEY: ${{ secrets.DEVSYNC_API_KEY }}
          DEVSYNC_PROJECT_ID: ${{ secrets.DEVSYNC_PROJECT_ID }}
```

**GitLab CI Example**:
```yaml
schema-check:
  script:
    - npm install -g @devsync/cli
    - devsync scan --db $DATABASE_URL --fail-on-mismatch
  only:
    - merge_requests
    - main
```

#### 4. Configure Failure Behavior

- **Fail on any mismatch**: `--fail-on-mismatch`
- **Fail on errors only**: `--fail-on-error`
- **Continue on warnings**: Default behavior
